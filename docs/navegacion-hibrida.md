# Navegación híbrida: detalles técnicos

[Volver al README](../README.md#navegación-híbrida-cdp--ui-automation)

El modo predeterminado `hybrid` combina CDP, mediante `playwright-core`, para las operaciones dentro de la web y `@microsoft/winappcli` con Windows UI Automation para el inicio de sesión y los controles nativos de Brave. Usa el navegador, perfil y sesión existentes: no descarga ni abre otro navegador, no instala extensiones y no copia cookies ni almacenamiento. Las operaciones CDP se dirigen a una pestaña SUNAT vinculada; no seleccionan esa pestaña ni activan la ventana, por lo que puedes trabajar en otras aplicaciones o pestañas.

Configura `SUNAT_CDP_ENDPOINT=http://127.0.0.1:9222` si Brave ofrece su depurador local. Se comprueba que el puerto pertenece a Brave y que el WebSocket usa el mismo puerto local. También se admite el metadato `DevToolsActivePort` del perfil estándar de Brave cuando `/json/version` no está disponible; no se lee almacenamiento del navegador. Se reutiliza una pestaña HTTPS de SUNAT. Si no hay ninguna, se abre automáticamente el acceso oficial en una pestaña de segundo plano del contexto existente, mediante la misma conexión CDP. No se cambia la pestaña activa ni se crea otro perfil o navegador. Varias pestañas SUNAT requieren resolver la selección de cuenta; una apertura fallida o incierta no se repite. Si la pestaña vinculada se cierra o cambia de sitio, sus controles quedan invalidados antes de volver a resolver el destino. No se leen documentos de pestañas ajenas ni marcos de otros dominios.

Si CDP no está disponible, el modo híbrido devuelve un diagnóstico y no cambia silenciosamente a ratón o teclado de Windows. El MCP no reinicia Brave ni habilita la depuración automáticamente. El ajuste explícito `SUNAT_BROWSER_MODE=uia` conserva el modo anterior, que puede activar Brave. El inicio de sesión y los controles nativos siguen usando UI Automation y pueden requerir temporalmente el foco. CDP no se usa para leer ni escribir Clave SOL.

Se mantiene una sola conexión CDP durante la vida del proceso MCP; las solicitudes simultáneas comparten también el intento inicial. Los lotes no crean clientes temporales. Si la conexión falla o se pierde, se detiene sin volver a solicitar depuración; para iniciar otra conexión hay que recargar el MCP expresamente. `sunat_estado` informa el estado local `idle|connecting|connected|blocked|closed` sin abrir conexiones CDP ni provocar una autorización del navegador. Una sesión nueva del navegador o del MCP puede requerir una nueva autorización; no se promete un permiso permanente.

El adaptador DOM fijo `src/cdp-page.js` se recarga al obtener un snapshot si cambia su contenido. Conserva el proceso MCP, la pestaña y la misma conexión CDP: no requiere otra autorización de depuración por editar ese archivo. No instala observadores ni sondeos; comprueba el archivo únicamente al usar el adaptador. Cada versión nueva renueva las referencias del documento y la huella de aprobación. Si el archivo cambia entre una lectura y un clic/relleno/desplazamiento dirigido, detiene esa acción y pide una lectura nueva. Si está incompleto, no se puede leer o tiene un error de sintaxis, detiene la navegación sin ejecutar la versión anterior; al corregirlo basta otra lectura. Las pruebas usan un navegador simulado y comprueban una sola conexión durante las recargas y la recuperación.

El 24/10/2026 se comprobó la recarga del adaptador sobre la conexión CDP ya abierta: una corrección para copias idénticas de filas del mismo submenú se aplicó con un snapshot nuevo y renovó las referencias sin reiniciar MCP ni reconectar Brave. Solo se omiten filas hermanas con el mismo ID canónico y HTML idéntico; acciones o ramas diferentes conservan su ambigüedad. Después se abrió el formulario inicial de Boleta de Venta Electrónica por Empresas → Comprobantes de pago → SEE - SOL → Boleta de Venta Electrónica → Emitir Boleta de Venta. Se comprobaron sus campos y el botón Continuar, sin completar ni emitir un comprobante. Es una ruta observada, no una emisión verificada.

Esta recarga cubre el archivo DOM local, incluidos sus selectores y clasificación de menús; no sustituye el reinicio necesario al cambiar herramientas, código TypeScript del servidor o dependencias. Para instalar el mecanismo en un proceso que ya cargó la versión anterior se necesita una recarga inicial del MCP. Reiniciar el MCP o Brave puede volver a requerir autorización, independientemente de la recarga del adaptador.

CDP ejecuta únicamente operaciones locales fijas del adaptador, sin aceptar JavaScript del modelo. Se conecta con `noDefaults` para conservar la configuración del navegador personal. Las referencias se ligan al marco, documento y elemento actuales; los valores del formulario y las URL reales permanecen en memoria para las mismas comprobaciones de aprobación tributaria. Los resultados indican `transport: cdp|uia`; las lecturas CDP también muestran `pageHasFocus`, que describe el foco del documento, no el de Windows. Ningún error de acción provoca un clic de respaldo por otro transporte.

Los desplazamientos CDP centran la etiqueta propia del menú para evitar la cabecera fija de SOL. Los clics comprueban documento, disponibilidad, marcos visibles y el elemento que recibe el punto de entrada; una superposición bloquea el clic. No esperan animaciones de estabilidad de una pestaña oculta. Esto evita tanto el clic en un submenú por el centro geométrico de su contenedor como esperas visuales que necesitan primer plano.

Las credenciales importadas se descifran localmente con DPAPI y se escriben en Brave con teclado nativo. Un proceso de entrada se inicia cuando hace falta y se reutiliza mientras vive el MCP; no instala un servicio. Los valores sensibles pasan por stdin, nunca por argumentos ni registros. Antes de escribir comprueba la ventana, el foco y cada campo previsto, incluido el de contraseña. Al cambiar de cuenta, intenta cerrar la sesión SUNAT anterior en esa misma ventana y se detiene si no puede verificar el cierre.

Los snapshots exponen controles de la página con referencias estables entre lecturas; excluyen la barra del navegador y las otras pestañas. CDP incluye los marcos HTTPS de SUNAT y sustituye referencias cuando cambia el documento. UI Automation reutiliza el identificador de ventana y su raíz de documento; resuelve pestañas con búsqueda de tipo `TabItem`, distinguiendo SOL de documentos cuyo título menciona SUNAT. Los recorridos esperan etiquetas concretas por su transporte. Al terminar cada llamado nativo libera el turno de escritorio de WinApp.

La lectura de URL prioriza el documento visible y reconoce direcciones de Brave con `https://` oculto, incluso si contienen una URL de redirección. Para reutilizar una sesión exige también un control visible de cierre de sesión; una URL del menú por sí sola no acredita autenticación.

En modo UIA hace una lectura superficial de las pestañas y la barra antes de localizar SOL. Si SUNAT reemplaza un documento embebido, una lectura fallida puede redescubrirlo sin repetir la acción anterior. En CDP los selectores HTML se completan por etiqueta con `fill`; en UIA se abren con un clic nativo, sin forzar InvokePattern en controles que usan selección o expansión.

Las URL públicas de snapshots, resultados y solicitudes de aprobación omiten todos los parámetros y fragmentos, también en servicios posteriores al login. La URL real se conserva únicamente en memoria para comprobar navegación y aprobación; nunca se devuelve. Esto evita exponer información de sesión serializada en direcciones de servicios SOL.

Las rutas guardadas reutilizan padres de menú expandidos y pueden volver mediante «Ir al inicio» cuando un servicio oculta los perfiles. El adaptador espera las animaciones propias de SOL antes de medir el punto del clic. Las esperas de destino descubren marcos oficiales que se agreguen durante la carga, sin capturas ni sondeo de fondo. Una ruta puede declarar `destinationChecks` para exigir señales de su formulario: NPS usa sus criterios y filtros en lugar de un supuesto campo Periodo. Los fallos conservan `code` y, cuando se conoce, `actionDispatched`; no reintentan una entrada incierta.

Si un enlace exacto y único queda fuera de vista, la ruta lo revela y toma una lectura nueva antes de actuar; varias coincidencias o un cambio de sesión detienen el recorrido. El aprendizaje exige evidencia nativa/DOM de menú y excluye acciones de formularios. Los perfiles antiguos omiten rutas de controles como «Continuar», «Buscar» y campos de pago; la siguiente escritura limpia esos registros y conserva las rutas válidas, sin límites de longitud o cantidad. Los avisos observados de registro de empleador y validación de afectación también detienen el servicio afectado; no se guardan permisos ni se eluden requisitos.

Para el acceso nativo se reconocen los formularios oficiales de autenticación estándar y anual, incluido su botón «Entrar». Las ventanas auxiliares propiedad de la ventana de Brave no se confunden con una segunda ventana principal; no se elige entre ventanas principales reales. Los avisos de acceso u obligación de SUNAT detienen la operación afectada, sin guardar permisos ni eludir su restricción. Cuando faltan señales específicas del formulario, la espera se interrumpe ante un aviso y vuelve a leer la pantalla; un título de menú o panel provisional no confirma el destino.

El autocompletado recorre los grupos nativos de Brave y reconoce una única sugerencia aunque Chromium la exponga como filas anidadas. Usa el patrón de selección de UI Automation para elegirla; el clic físico sobre ese menú puede ser rechazado por Windows al tener otra ventana el foco. Si falla, devuelve un código de diagnóstico sin incluir la credencial.

Los cuatro accesos públicos se consultan mediante `entryPoint`: `declaraciones-pagos`, `tramites-consultas`, `renta-anual-personas` y `renta-anual-empresas`. Sus direcciones públicas y procedencia se documentan en `data/operation-index.json`; no se guardan redirecciones OAuth, estado de sesión ni credenciales. Renta Empresas abre su página oficial de entrada: no certifica la apertura del 710 ni selecciona una campaña. Los botones conocidos de `sol.html` también navegan en la misma pestaña.

Para ventanas excepcionales, el MCP escucha únicamente durante el clic, comprueba el vínculo con la página de origen, el contexto existente y el destino HTTPS SUNAT. Las aperturas múltiples, ajenas o no verificables detienen la acción. No se cierra ninguna ventana del usuario ni se solicita otra conexión CDP. `contextChanged:true` invalida las referencias y aprobaciones, y la cuenta importada se verifica otra vez. Las ventanas que el propio sitio requiera pueden aparecer en pantalla; el MCP no las activa y mantiene el login nativo separado.
